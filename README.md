# AI-buddy

ИИ-помощник инженерного стажёра: от вопроса о доступе к тестовой БД до
проверенного результата и улучшения инструкций для следующей группы.
Прототип для трека Авито Hack&Change 2026.

Помощник объясняет следующий шаг, находит разрешённые источники и готовит действия.
Заявку подтверждает стажёр, доступ одобряет отдельный согласующий, а готовность
засчитывается по результатам IAM/DB-проверок. Повторяющиеся затруднения становятся
предложениями для человеческого review. Ответ модели не выдаёт права и не меняет прогресс.

## Возможности

- Цели, подзадачи, blockers, следующие действия и лента доказательств в одном workspace.
- Сдача DB-задания с доказательством проверки и выводом стажёра. Автор ТЗ принимает работу или возвращает её с комментарием.
- Контекстный чат с RAG, ссылками на инструкции, объяснением терминов и меткой источника ответа.
- Заявка → подтверждение → одобрение → IAM → безопасная проверка подключения к mock БД.
- ТЗ наставника: черновики, неизменяемые опубликованные версии и назначения стажёрам.
- Preview вопроса наставнику для ручной отправки в Telegram.
- Отчёты о повторяющихся неясностях, AI-предложение правки, выбор изменений и отдельная публикация.
- Сравнение версий по зарегистрированным затруднениям с защитой малых групп.

Корпоративные IAM/DB и аккаунты синтетические. Инструкции не являются регламентами Авито.

## Быстрый запуск

Нужны **Docker Engine/Desktop**, **Docker Compose v2** и **Python 3.12**.
Для первой сборки нужен доступ к registries образов и пакетов. Node, Go, PostgreSQL
и Python-зависимости устанавливаются внутри образов.

```sh
git clone https://github.com/egrsid/ai-buddy-avito.git
cd ai-buddy-avito
python3 -m scripts.demo up --project ai-buddy-demo-review
```

Откройте **http://localhost:15173**. Go API: http://localhost:18080.
Старт применяет миграции, загружает тестовые данные и индекс знаний, затем ждёт readiness.
Пароли вводить не нужно: в локальном интерфейсе выберите демо-аккаунт.

Этот режим не требует API-ключа: AI-ответы детерминированные и помечены «без ИИ».
Пользовательские действия выполняются через настоящие Go/AI/mock/PostgreSQL-компоненты.
Для ответов реальной модели подключите ключ по разделу ниже.

```sh
python3 -m scripts.demo status --project ai-buddy-demo-review
python3 -m scripts.demo down --project ai-buddy-demo-review
```

Остановка сохраняет данные. Для чистой повторной проверки задайте новое имя
`ai-buddy-demo-*`; не удаляйте существующие volumes. Если порты заняты, освободите
15173/18080 или задайте `DEMO_FRONTEND_PORT` и `DEMO_BACKEND_PORT` при запуске.
На Windows команды можно выполнять в WSL; в терминале с командой `python` используйте
её вместо `python3`.

## Тестовые данные

| Аккаунт | Роль и назначение |
|---|---|
| `intern-a` | Стажёр команды A, основной сценарий доступа |
| `intern-b` | Второй стажёр команды A для проверки повторяющегося затруднения |
| `buddy-a` | Наставник команды A, автор ТЗ и reviewer отчётов понятности |
| `approver-a` | Согласующий доступа к `db-team-a-test` |
| `docs-owner-a` | Владелец документации, рассматривает Knowledge Gap Candidates |
| `intern-c`, `buddy-b` | Команда B для отрицательных проверок доступа |

Дополнительные аккаунты раскрываются переключателем «Дополнительные участники».
Разрешённая роль БД — `db_reader`. Данные и маршруты находятся в
[data/seed](data/seed), учебные инструкции — в [data/knowledge/v2](data/knowledge/v2).
Это тестовый ресурс mock-сервиса, а не доступ к внутренней PostgreSQL приложения.

## Порядок проверки

1. Под `intern-a` начните цель доступа к БД, откройте шаг и спросите AI о заявке.
2. Проверьте preview и подтвердите отправку: появится submitted-заявка.
3. Под `approver-a` одобрите её. После свежей IAM-проверки вернитесь к стажёру.
4. Проверьте подключение с SSL `disable`: ожидается `DB_SSL_REQUIRED`. Повторите
   с `require`: техническая цель подтверждена. Обновление страницы сохраняет результат.
5. Повторите ошибку под `intern-b`: `docs-owner-a` получит один candidate для review.
6. Под `buddy-a` создайте и опубликуйте ТЗ, назначьте обоим стажёрам. Одинаковые
   отметки «Непонятно» создадут отчёт; AI-правка применяется в draft и публикуется отдельно.

[Подробные шаги и ожидаемые результаты](docs/verification.md) включают Telegram,
ACL, mobile/keyboard и сравнение версий. Для контрольной семидневной истории:

```sh
python3 -m scripts.v4_cohorts up
```

Отдельный стенд http://localhost:15181 показывает 6/10 → 2/10, то есть −40 п.п.
Это явно помеченные **синтетические данные**, не измеренный эффект на сотрудниках.
На свежей основной БД «Недостаточно данных» — корректный результат.

## Подключение реальной LLM

Провайдер — Cloud.ru Foundation Models, OpenAI-compatible API. Используются
`GigaChat/GigaChat-3-Pro`, резервная `ai-sage/GigaChat3.5-432B-A28B` и embeddings `BAAI/bge-m3`.
Эксперт может использовать свой ключ с доступом к этим моделям.

```sh
cp .env.example .env.live-v4
```

В локальном файле заполните:

```dotenv
LLM_MODE=live
LLM_PROVIDER=openai
LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1
LLM_MODEL=GigaChat/GigaChat-3-Pro
LLM_FALLBACK_MODEL=ai-sage/GigaChat3.5-432B-A28B
LLM_API_KEY=<собственный ключ Cloud.ru>
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_DIM=1024
FRONTEND_PORT=15180
BACKEND_PORT=18087
LLM_BUDGET_STOP_RUB=20
```

Сверьте цены `LLM_PRICE_INPUT_RUB`, `LLM_PRICE_OUTPUT_RUB`, обе `LLM_FALLBACK_PRICE_*`
и `EMBEDDING_PRICE_RUB` с тарифами своего аккаунта: значения в example — пример
конфигурации. Ключи и локальные `.env*` исключены из Git и Docker context.

```sh
python3 -m scripts.live_demo check --env-file .env.live-v4
python3 -m scripts.live_demo up --env-file .env.live-v4 --project ai-buddy-live-v4
python3 -m scripts.live_demo budget --env-file .env.live-v4 --project ai-buddy-live-v4
```

Сайт с реальной моделью: **http://localhost:15180**. При сбое/исчерпании бюджета
интерфейс честно показывает резервный ответ или fallback. Постоянный ledger общий
для управляемых live-вызовов, сохраняется после restart и не обнуляется при запуске.
Если на машине уже есть расходы выше выбранного порога, новые платные вызовы блокируются;
это не причина удалять ledger. Пример конфигурации не содержит рабочего ключа.

## Архитектура и стек

React вызывает только Go. Go владеет состоянием, правами, действиями и trusted evidence;
Python/FastAPI — AI и знаниями; отдельный corporate mock имитирует IAM/DB.
PostgreSQL разделена на app/kb/corporate с отдельными runtime-ролями.

| UI | React, TypeScript, Tailwind, TanStack Query, Zod; версии в [package.json](frontend/package.json) |

## Тесты и покрытие

```sh
make install
make check
make test
```

Для `make test` нужны host toolchains и отдельная подготовленная тестовая БД.
[Полные команды](docs/testing.md) описывают её создание, component checks,
PostgreSQL/pgvector tests, Playwright и настоящий restart.

Независимое покрытие строк: **Go 83,03%**, **AI 96,90%**, **corporate mock 98,05%**,
**frontend 95,66%**. Порог ≥82% для каждого компонента.
[Отчёт](docs/coverage/README.md) содержит исходные профили, область измерения,
SHA-256 исходников и команду пересчёта; результаты CI и локальные измерения различены.

## Ограничения

Demo-login рассчитан на локальную проверку, не на публичное production-размещение.
Реальные SSO/корпоративные adapters не подключены. Telegram экспортирует preview;
сообщения отправляет человек. AI не выполняет произвольный SQL/команды, не утверждает
доступ, не засчитывает готовность и не публикует инструкции автоматически.
Автоматическая правка критерия приёмки ограничена первым критерием; остальные доступны
в ручном редакторе. Реальная экономия времени и причинный эффект пока не измерены.
