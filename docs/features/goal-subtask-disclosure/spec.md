# Цели с раскрываемыми подзадачами — specification v3

PLANNED, не реализовано. Задачи V3-GOALS-BE-01, V3-GOALS-FE-01.
[Общий план](../../v3/delivery.md), [Product](../../v3/product.md).

Страница стажёра показывает список его целей, а не общий плоский список подзадач.
Каждая цель — отдельная карточка: название, состояние, число проверенных обязательных
подзадач из общего числа, progress-bar и кнопка «Раскрыть подзадачи». По умолчанию карточки
свёрнуты; допускается раскрыть несколько независимо. Внутри — упорядоченные подзадачи
именно этой цели с зависимостями/состоянием/блокером и переходом в существующую деталь шага.
Повторное нажатие сворачивает список, не меняя прогресс и состояние задачи.

Прогресс приходит из Go: floor(verified mandatory steps / total mandatory steps × 100).
Для 0 шагов — 0% и «Подзадачи ещё не заданы», не 100%. Claims, ответ LLM, сообщение в
Telegram, draft/approval и раскрытие карточки не засчитываются как выполнение. Optional
шаги показываются отдельно и не меняют знаменатель; mandatory/dependency задаёт утверждённый
маршрут. Простые разделы ТЗ — не автоматически mandatory steps. Редактор ТЗ не генерирует
новые технические проверки. При инвалидации evidence прогресс может уменьшиться.

Стажёр видит все свои разрешённые цели (не только goals[0]); empty/loading/error/нет прав,
blocked/completed и устаревшие данные обозначены явно. Раскрытие без мыши: button,
aria-expanded/aria-controls, Enter/Space, прогресс с текстом и accessible value.
Открытие шага по прямой ссылке работает и для свёрнутой родительской карточки; возврат
сохраняет раскрытие в пределах вкладки/сессии и текущего пользователя, смена аккаунта
сбрасывает его. Опрос/обновление цели не должно самопроизвольно сворачивать карточки.
Сохранить выбранные цвета/типографику/отступы main; новый экран не переносит бизнес-логику в FE.
