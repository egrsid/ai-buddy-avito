# Avito AI-buddy — Engineering Onboarding & Feedback Loop

Версия 2.0 · 2026-11-11 · основание: [replan brief](../../CODEX_PROJECT_REPLAN.md).
Это целевое видение; продуктовые возможности ещё предстоит реализовать.

Стажёру нужна помощь от рабочей цели до проверенного результата. Чат, поиск,
чек-лист и создание заявки сами по себе не показывают готовность к инженерной работе.
Наставнику нужны уже выполненные проверки и конкретная причина остановки. Организации
нужен сигнал о повторяющихся затруднениях, чтобы следующие стажёры не повторяли тот же путь.

Avito AI-buddy использует утверждённые маршруты, учитывает права, предлагает безопасные
действия, проверяет результат доверенными сигналами и передаёт диагностический контекст
человеку. Повторяющиеся ошибки становятся предложениями улучшить инструкции и процессы.

Единый цикл: **Goal → Action → Evidence → Blocker → Buddy → Friction pattern →
Knowledge Gap Candidate → human review**. Названия Engineering Readiness Navigator,
Dependency-aware Unblocker, Proof of Readiness, Buddy Debug Bridge и Reverse Onboarding
обозначают механизмы одного продукта.

Главное отличие для демонстрации — сочетание проверяемого прогресса, причин блокеров,
передачи человеку и обратной связи организации. Аналитическая перспективность этой
комбинации не доказывает абсолютную уникальность на рынке. RAG, tool calling, MCP,
суммаризация и число агентов сами по себе не являются заявленным отличием.

Главный MVP-маршрут: получить доступ к синтетической тестовой БД команды и проверить
подключение. Practice First означает предложить безопасную проверку после объяснения.
Утверждение пользователя и ответ AI не заменяют evidence. Проверки MR/code style,
IDE и произвольные репозитории относятся к P2; AI не заменяет code review наставника.

Приоритеты, правила и приёмка: [Product Spec](specification.md).
Пятиминутная история: [демонстрация](demo.md). Исследование и созвоны известны по brief;
их оригиналы в репозитории отсутствуют, выводы не выдаются за независимо проверенные факты.
