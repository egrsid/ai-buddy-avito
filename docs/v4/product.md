# Product v4

Target, не реализация. [Пакет](README.md), [delivery](delivery.md).

## Сценарий и ценность

Стажёр открывает рабочий результат, видит назначенное ТЗ и технический маршрут.
Безопасная проверка объясняет blocker; AI предлагает действие по разрешённым источникам.
Два независимых сигнала неясности одного раздела создают task report. Автор проверяет
гипотезу, получает AI-предложение с diff, вручную правит draft и публикует successor.
Следующая группа получает новую версию. Система сравнивает наблюдения после равного
периода экспозиции и показывает ограничения, а не объявляет причинный успех.

Главная демонстрационная мысль: компания видит, какие исправления стоит проверять на
следующих новичках. Официальная матрица жюри неизвестна; рост оценок не обещается.

## Роли

| Роль | Доступ v4 |
|---|---|
| Intern | Свои workspaces/цели/назначения, safe checks, Telegram, структурированные отметки |
| Mentor / buddy | Собственные ТЗ/reports/proposals/impact; явное связывание своих назначений с допустимым маршрутом |
| Access approver | Прежние назначенные ресурсы и отдельные решения; не получает editor автоматически |
| Documentation owner | Прежние scoped candidates/instructions; не получает персональную timeline стажёра или чужие task reports |
| Demo operator | Разработчик в local/test harness, не новая прикладная роль и не публичный API управления данными |

## Границы P0

1. Один DB journey и одна family ТЗ с двумя версиями; несколько независимых workspaces
   и состояния без связи также поддерживаются. Нет генерации обязательных этапов LLM.
2. AI diff только для TaskBrief section/goal/result/criteria; исходный task report обязателен.
   Редактор документации/автозапись в kb вне P0; docs feedback v3 сохраняется.
3. Сравнение эффекта P0 только task clarity по версиям ТЗ. Технические попытки и их
   evidence показываются отдельно. Эффект правки документации — P1 после достоверной
   истории exposure/version; нельзя смешивать его с task clarity.
4. Timeline P0 — существующий DB flow, актуальный blocker и permitted recovery.
5. Demo P0 — изолированный synthetic offline стенд, actual-live smoke отдельным gate.

P1: подтверждённая наставником ручная приёмка рабочего результата (отдельная от verified),
эффект правок инструкций, расширенная статистика времени, экспорт отчёта.
Не входят: HR-рейтинг, бот/чтение Telegram, автопубликация, реальные IAM/DB интеграции,
произвольные SQL/команды, переписывание journey AI, дополнительные агенты ради числа агентов.

## Продуктовые состояния

Workspace показывает две независимые оси: technical ready/unverified/blocked по Go и
pinned brief version с «приёмка результата не ведётся автоматически». Общего процента
из разных осей нет. All technical goals verified → поздравление, без повторного маршрута.
Связь или её удаление, публикация ТЗ, copy/open Telegram не меняют technical state.

RevisionProposal: requested → ready | needs_input | unavailable; ready → applied_to_draft
или discarded. Needs_input требует ответа человека и новой generation revision; прежний
ответ не перезаписывается. Publish — существующая отдельная операция автора.

ImpactComparison: collecting / available / insufficient_data / not_comparable.
Available означает возможность показать описательные показатели, не «исправление доказано».
Report resolved означает связанную human-published версию, не успешность эксперимента.

## Измеримый успех v4

- Пользователь без подсказки находит следующий допустимый шаг и причину статуса.
- Reviewer видит различие evidence/approval/claim/AI hypothesis, проверяемое API.
- Diff прослеживается до одного отчёта и версии; stale/revoked proposal не применяется.
- Счётчики comparison совпадают с фиксированным oracle и не раскрывают малые группы.
- Offline/primary/secondary/unknown отображаются по серверу; paid smoke не подменяется fixture.

Пользовательский usability-прогон: 3–5 добровольцев на synthetic данных, наблюдать завершение
сценария и места непонимания. Это качественная проверка, не статистическое доказательство
рыночного эффекта. Реальные ROI/сэкономленные минуты не заявлять до измерения.
