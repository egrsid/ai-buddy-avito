## Что исправлено в этом проходе

| Проблема | Последствие | Исправление |
|---|---|---|
| Go закрывал пул БД сразу после начала Shutdown (`ListenAndServe` возвращается до окончания drain) | при перезапуске текущие запросы падали (`conn busy`) или зависали; плавающие e2e после restart | `Server.Serve`: ждём запросы и фоновую AI-работу (`Background`/`WaitBackground`), потом закрываем пул; тесты с `-race` |
| Скрипт live-приёмки без `Accept: text/event-stream`, ожидал `completion=completed`, не учитывал лимит 5 запусков/мин | live-приёмка через Go не могла пройти ни разу (422, ложные FAIL, 429) | заголовок, значение `complete` по контракту, ожидание лимита; тесты-двойники повторяют поведение Go |
| `live_demo evals` писал отчёт в read-only `evals/` контейнера | платный прогон терялся на записи | `--report /tmp/...`, копия в `.cache/v4-revision-live.md` |
| Стенд когорт и `--cached-build` требовали образы с машины TL | на любой другой машине (и у жюри) не запускались | оверлей offline только если образы есть, иначе обычная сборка |
| Один потерянный connect к Cloud.ru включал предохранитель на 30 с | следующий вопрос уходил на запасную модель | повтор подключения 2 × 2.5 с (запрос не отправлен — бесплатно), причина сбоя в логе |
| Поток модели, закрытый после `finish_reason` без `[DONE]`, считался обрывом | полный ответ помечался interrupted | `finish_reason stop/length` = полный ответ; обрыв без него — по-прежнему сбой |
| В AI не передавалась гипотеза отчёта | модель хуже понимала, что править | `revisionReport`: безопасный агрегат + гипотеза ≤2000 символов, без ID стажёров (проверяет фейк AI в Go-тестах) |
| Сверка снимка контрактов и тест путей падали на Windows из-за CRLF/`\` | `make check` красный у разработчика на Windows | хеш без CRLF (на Linux значения те же), переносимая проверка пути |
| Лог неизвестной ошибки Go — только тип | причину сбоя не найти | маршрут, цепочка типов, SQLSTATE, отмена; без текста ошибки и данных; отменённые браузером запросы не считаются сбоем |
| Каждый вопрос открывал новое TLS-соединение к Cloud.ru (httpx закрывает простой через 5 с); на сети с потерями пакетов подключение шло 1–3+ с при лимите 2.5 с | на стенде 15180 первые 2 из 10 вопросов ушли в шаблон «без ИИ» (обе модели — ConnectTimeout) | соединение держится 90 с и раз в 25 с освежается бесплатным `GET /models`; лимит подключения 3.5 с. Повтор live: **10/10 primary**, первый текст 2.6–5.0 с |
| Локальные заметки попадали в Docker-образ | лишние файлы в образах | `.dockerignore` |
| Панель «Маршруты назначений» (у лида теперь «технические цели назначений») — управляемый `<details>`, состояние менялось при загрузке списка | панель закрывалась под пользователем при >3 назначениях; браузерный сценарий падал на таком стенде | состояние выбирается один раз после загрузки, дальше решает пользователь; unit-тесты |

## Что остаётся решением людей

- Формальное утверждение контрактов командой (G1 lock): тестами не заменяется.
- AI-правка касается одного поля отчёта (раздел, цель, результат или первый критерий);
  несколько критериев — ручной редактор.
- Эффект за 7 дней виден только на синтетической истории с тестовыми часами; на свежей
  демо-БД корректный ответ — insufficient_data.
