# Понятность интерфейса и подготовка main · 14 ноября 2026

Поручение владельца: объяснить сценарий улучшения ТЗ, убрать fixtures/ссылку на
прототип, прояснить связь ТЗ с DB-целью, подготовить защиту и локальное слияние.
Работа в feature/tl-v4; main и исходные ветки участников не переписываются, push/PR нет.

## Что изменено

- «Рабочие результаты» переименованы в «Задания и цели». На странице объяснены
  назначение раздела, связь с «Моими целями» и «ТЗ от наставника», отличие технической
  готовности от человеческой приёмки рабочего отчёта. Видно название связанной цели.
- В «Улучшении заданий» пояснены источник отчёта и дальнейшие действия. После выбора
  отчёта явно показаны ТЗ, версия, раздел и число участников, к которым относится правка.
- Настройка DB-цели выделена в дополнительный блок. Для каждого назначения видны
  ТЗ/версия/стажёр; действие появляется после явного выбора «нужен доступ к БД».
  Для собственного ТЗ без БД оно не обязательно. После сохранения показаны состояние
  и следующий шаг стажёра: preview/confirm связи → проверки → отдельное согласование доступа.
- Go отдаёт аддитивные необязательные флаги db_route_enabled (assignment v3) и can_link
  (workspace card v4), FE strict schemas обновлены. Поэтому выбор виден после refresh,
  а неподходящее действие стажёра не предлагается. Миграций и изменения прав нет.
- Fixtures и контролы тестовых состояний убраны из сайта: development/production
  всегда используют Go, старые настройки sessionStorage/preset игнорируются. Fixtures
  остаются для изолированных unit-тестов; состав coverage/exclusions не уменьшен.
- Нижняя ссылка «V4 · прототип без записи данных» удалена. Она вела на отдельный
  ранний макет, а не описывала статус всего продукта. Старая закладка /v4-preview
  теперь показывает реальный раздел текущей роли. Прототипные компоненты остаются тестовыми.
- [Полная инструкция](../../TESTING_FINAL_V4.md), раздел 5: конкретный пример ТЗ,
  две отметки, выбор отчёта, вопрос модели, авторский ответ, diff, draft, отдельная
  публикация, переход стажёра и закрытие отчёта. Добавлена таблица смысла операций.
- [Сценарий защиты](../../JURY_DEMO_V4.md): время, экраны, текст выступления, все пять
  направлений v4, подготовка и короткая версия. [Публикация](../../MAIN_RELEASE.md)
  описывает локальный release snapshot и команды владельца для GitHub main.

Ранний запуск нашёл проблемы самого harness: неустановленный bundled Chromium
(использован установленный Chrome), статический Origin 5173 для другого порта и
выбор первого checkbox вместо checkbox правки. Origin выводится из baseURL,
checkbox выбирается по контексту diff. Одновременные Playwright-процессы конфликтовали
за test-results: итоговые наборы запускались последовательно.

AI и corporate mock в этом UX-изменении не менялись; их независимые результаты
541/96,86% и 6/98,05%, а также actual LLM evidence остаются в
[предыдущем отчёте приёмки](final-acceptance-2026-11-14.md). Новых платных генераций
ради изменения подписей не выполнялось. Live-стенд пересобран, данные/бюджет сохранены.
Formal external approval, Go race, cold build и remote CI не объявляются выполненными.

## Подготовка слияния

main является предком feature/tl-v4; локальные изменения фиксируются коммитом,
release/v4-main указывает на проверенный итог. Слияние возможно fast-forward.
Основной сайт http://localhost:15180, история когорт http://localhost:15181.
Окончательное движение main на GitHub выполняет владелец по корневой инструкции.
