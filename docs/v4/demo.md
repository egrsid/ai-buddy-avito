# V4 — сценарий демонстрации после реализации

План, не проведённая демонстрация. [Матрица/gates](testing.md), [scope](product.md).
Владелец подтверждает время выступления; baseline 5–7 минут, два независимых блока.

## Основной offline блок

| Время | Действие | Проверяемое свидетельство |
|---|---|---|
| 0:00–0:45 | Intern открывает один workspace: результат, ТЗ, technical steps | Ясно, зачем шаг, что уже проверено, чего не хватает |
| 0:45–1:45 | Confirm request → approver → IAM → failed SSL check | Timeline разделяет отправку, разрешение, доступ и проверку |
| 1:45–2:15 | Safe Telegram preview, без отправки; retry require | Scope-filtered контекст; только успешный check даёт verified |
| 2:15–3:00 | Вторая независимая неясность раздела ТЗ → один report | Distinct threshold, наблюдение отдельно от гипотезы |
| 3:00–4:15 | Автор получает diff, уточняет неизвестный срок, применяет в draft, публикует | AI помогает; человек принимает и публикует; old assignment pinned |
| 4:15–5:15 | Открывает сравнение двух synthetic когорт | Назначено/eligible/affected, одинаковые окна, limits, описательная разница |
| 5:15–5:45 | Foreign account negative / reload | Нет чужих title/count; прогресс/решения сохраняются |

Историю двух семидневных когорт оператор готовит заранее на отдельной synthetic базе;
на экране постоянно «синтетические данные / тестовые часы». Нельзя делать вид, что за
минуту прошла реальная неделя. В comparison пример 10/6 → 10/2 — иллюстрация механизма,
не реальный бизнес-эффект. Неподготовленные данные дают no-data, без демонстрационных чисел.

## Отдельный actual-live блок

После явного live решения владельца: primary разбирает неоднозначный раздел и даёт
validated diff; затем ACL negative; отдельно оператор показывает controlled outage и
честный fallback/manual editor. Primary/usage подтверждаются сохранённым manifest,
а не текстом «я ИИ». В CI этот блок fake-provider, не actual live.
При отсутствии live gate показать offline demo и прямо назвать, что не проверено.

## Перед выступлением

TL проверяет commit/schema/dataset revisions, новый isolated project и порты, readiness,
ledger/лимит, account switching и browser scenario. FE снимает desktop/mobile screenshots
и проводит короткий usability walkthrough. AI проверяет кейсы/valid sources без реальных
данных. QA сверяет oracle и отрицательную матрицу. Основная v3 demo DB сохраняется.

Подготовить короткую запись работающего сценария как резерв и явно назвать её записью;
не заменять ей живые provider evidence. Вопросы жюри «почему verified», «кто разрешил»,
«как считали эффект», «что при сбое LLM» отвечаются соответствующим экраном/manifest.
Ни gate, ни отсутствие входных данных не скрываются сменой label.
