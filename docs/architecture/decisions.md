# Архитектурные решения

Версия 1.0 · 2026-11-10 · рабочая база для старта команды.

Основание: текущая архитектура, предложения из приложений и поручение Tech Lead
подготовить недостающие договорённости. Это новые зафиксированные решения для разработки,
а не свидетельство прежнего согласования приложенных файлов. Реализация отслеживается в backlog.

## Обоснование и последствия

001–005 обеспечивают одного владельца данных, публичную точку авторизации в Go,
потоковый UX и независимую разработку AI. Python не читает app и corporate.
Go не читает kb напрямую: поиск и документ доступны через внутренний AI API.
Схема corporate принадлежит только mock-сервису; бизнес-заявки Go содержат внешний ID.

003: подтверждение связано с неизменяемым снимком параметров, пользователем и временем.
Повтор подтверждения возвращает существующий результат. Неопределённый результат mock-вызова
сверяется по ключу операции; новый ключ автоматически не создаётся.

004: поток нельзя запускать повторным GET. После разрыва frontend читает сохранённое состояние,
а не повторяет действие. Для MVP нет replay SSE и фонового продолжения генерации.

006: переключатель роли означает новый вход на сервере, а не изменение client-side роли.
Демо-вход включается только APP_ENV=local/test; публичное размещение требует отдельной
аутентификации, HTTPS и отключения демо-входа. Cookie и CSRF описаны в security.md.

008–010 уменьшают объём MVP. Ответ наставника атомарно закрывает обращение как resolved;
отдельной операции закрытия без ответа и полноценного мессенджера нет.

012: patch-версии и прямые зависимости закреплены в manifests/lock-файлах. Драйвер Go
для первой DB-фичи — pgx/v5 (закреплён в go.mod/go.sum); Python — psycopg3, миграции — SQL через общий runner;
frontend — Vite, Tailwind, TanStack Query и Zod. Zustand вводится только по задаче.

## Ещё не принято / внешние зависимости

- Конкретные люди и GitHub handles: TL заполняет working-agreements.md.
- Реальный LLM-провайдер, модель, embeddings, ключ и бюджет: AI готовит spike AI-01.
  До него действует mock-режим. Векторные размеры не фиксируются до выбора embeddings.
- Площадка публичной демонстрации и auth для неё: TL/Infra, до размещения.
- Подлинные материалы организаторов: TL сверяет требования и комплект сдачи.

## Изменение решения

Автор открывает PR с причиной, затронутыми контрактами, планом миграции и тестами.
Владельцы потребителей проверяют совместимость, TL утверждает. Старую запись не удалять:
пометить superseded и сослаться на новую. Обратное несовместимое изменение API до общей
интеграции требует синхронного обновления всех потребителей; после неё — новая версия API.
