# RP-QA-01 · Проверки целей и доступа

Статус: два API integration теста адаптированы к v2; прогон заблокирован до готовности
RP-AUTH-01 и RP-JOURNEY-01 и подключения согласованного RP-CONTRACT-01 baseline.
Тесты используют Playwright `APIRequestContext`, не являются браузерным E2E.

## Сценарии

1. **Цель и владение:** `intern-a` читает разрешённый journey, создаёт/получает активную
   Goal, сверяет steps и `progress.verified/total/percent`, перечитывает Goal. `intern-b`
   (та же team), `intern-c` (другая team) не получают Goal A (`404` для прямого чтения);
   `buddy-a` не имеет доступа к списку Goals (`403`). Все ID берутся из ответов API.
2. **Сессия и CSRF:** без сессии `/auth/me` и `/goals` возвращают `401`. Создание Goal
   без `X-CSRF-Token` возвращает `403 CSRF_INVALID`; список Goals после запроса не меняется.

Создание выполняется с Origin, cookie-сессией, CSRF-токеном и новым UUID
`Idempotency-Key`. Тесты не меняют состояние шагов и не используют старый PATCH status.

## Предусловия и запуск

- Использовать согласованный v2 contract baseline и v2 seed с `intern-a`, `intern-b`,
  `intern-c`, `buddy-a` и доступными journeys.
- Backend auth/journey endpoints должны быть готовы; UI, AI, buddy, reverse onboarding,
  миграции и restart не проверяются этими двумя тестами.
- Поднять Go API и frontend proxy на окружении, указанном `E2E_BASE_URL`/`APP_ORIGIN`.
- Команда из `frontend/`: `npx playwright test e2e/onboarding.spec.ts`.

## Ограничения и результат

Проверка version conflict относится к Backend (RP-VERIFY-01). Browser UI, reload/restart
и полный пользовательский feedback path относятся к RP-E2E-01/RP-INTEGRATION-01.
На 2026-11-12 контракты v2 доступны в командной ветке, но backend auth/journey runtime
ещё не реализован. Playwright тесты адаптированы по контракту; фактический прогон не
выполнялся и должен быть записан после появления endpoints. Не добавлять skip ради
зелёного статуса при недоступном API.
