# Версия 3 — рабочий пакет команды

13 ноября 2026. **Проектирование, runtime v3 не реализован.** База разработки — опубликованный
main b6f940d. Ветка текущей документации — docs/v3-planning. Сайт/БД остаются v2.
Основание — новые требования владельца после созвона и выбор Telegram в этой сессии.
Этот пакет заменяет прежний план только в затронутых областях; S1–S4 не возобновляются.

Порядок источников: требования владельца → [Product v3](product.md) → три SDD →
[границы/контракты](architecture.md) → [задачи и handoff](delivery.md) → [приёмка](testing.md).
Исполняемые contracts/v2 и код описывают v2, не готовые v3 schemas.

| Изменение | Спецификация | Владелец |
|---|---|---|
| Telegram вместо внутреннего обращения | [Контакт](../features/telegram-mentor-contact/spec.md) | BE + FE, AI для текста |
| Наставник редактирует и публикует версии ТЗ | [ТЗ](../features/mentor-task-authoring/spec.md) | BE + FE |
| Повторная неясность ТЗ → отчёт наставнику | [Обратная связь](../features/mentor-task-feedback/spec.md) | BE + AI + FE |

Сохраняются: DB journey, separate approval/IAM/evidence, RAG/ACL, offline/failover,
Go как владелец состояния, Python как AI/knowledge, documentation-owner feedback loop.
Не добавляются: Telegram bot, чтение переписок, автоотправка, HR-рейтинг наставников,
универсальный таск-трекер, автоматическое изменение ТЗ/документов/технических прав.

## Что команда может делать сейчас

По этому поручению меняется только документация. BE/AI/FE могут подготовить schema proposals,
fixtures и планы реализации в рамках своих следующих задач по плану; до contract gate
не закреплять несовместимые DTO. Назначения — в delivery.md, старые handoff ниже верхней
v3-вставки являются историей v2. Никаких push/PR от агента.

## Явные допущения для реализации

Редактор ТЗ находится в продукте; импорт из внешнего трекера не входит в v3.
Простая публикация наставником — человеческое подтверждение, отдельная роль редактора не нужна.
Порог отчёта 2 разных стажёра, окно 30 дней; это выбранный стартовый baseline, настраивает TL
до schema gate. Telegram username задаётся назначением наставника; реальные контакты
в Git/fixtures не записываются. До публичного релиза владелец утверждает retention/export
policy для реальных данных; local demo остаётся синтетическим.
