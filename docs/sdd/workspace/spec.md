# Рабочее пространство и лента доказательств — спецификация

## Цель и предусловия

Intern имеет assignments и/или свои goals. Автор задания при необходимости разрешил конкретный технический template.

## Пользовательский сценарий

Intern видит задания и технические цели → открывает разрешённый link preview → подтверждает связь → смотрит шаги, blocker, next action и объяснение статуса через timeline.

## Правила и критерии приёмки

- **WORK-01.** Связь assignment/goal задаётся только явным preview/confirm; совпадение названий или догадка AI не создают link.
- **WORK-02.** Разрешение DB-маршрута автором не выдаёт доступ. Для задания без БД связь не обязательна.
- **WORK-03.** Несколько заданий могут использовать один goal; verified и общие counters не удваиваются. Несвязанные сущности также видны.
- **WORK-04.** Workspace pages не теряют элементы за пределами первой страницы и фиксируют membership snapshot. Cursor чужого subject/scope отвергается.
- **WORK-05.** Timeline — только чтение trusted фактов с source/correlation/validity. Submitted, approved, IAM observed и DB passed различаются; старый успех не скрывает revoke.
- **WORK-06.** История без доказательств не выдумывается. Receipt cutoff/tie-breaker сохраняют страницы; ACL повторно проверяется на каждой странице и replay.
- **WORK-07.** Account switch очищает данные прошлого subject. Пустое/loading/error/forbidden состояния, 390px и клавиатура различимы; панель не закрывается сама при загрузке списка.

## Контрольный пример

Наставник разрешил DB-маршрут ровно для выбранного назначения. Intern проверил preview и связал его с существующей целью; история grant не была создана заново.
