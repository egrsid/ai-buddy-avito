**Ограничения:**
- Не изменяй несвязанные компоненты.
- Не меняй общие API-контракты и границы компонентов без согласования с Tech Lead.
- Не добавляй функциональность вне спецификации.
- Не реализуй HR-функции — они вне MVP.
- Добавляй тесты для изменённого поведения.
- Не коммить секреты.
- Соблюдай существующую архитектуру.

**Перед завершением:**
1. Выполни `make check` и проверки компонента по `docs/testing/strategy.md` и `Makefile`.
2. Обнови относящиеся к задаче SDD и статус backlog по фактическому результату.
3. Укажи изменённые файлы.
4. Перечисли реализованную функциональность.
5. Сообщи результаты проверок, проблемы и ограничения, включая проверки, которые не удалось выполнить.
6. Подготовь краткое локальное описание изменений для владельца репозитория.
