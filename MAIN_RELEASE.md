# Публикация финальной v4 в main

Рабочая ветка — `feature/tl-v4`. После локальных проверок её итог фиксируется
в `release/v4-main`. Эта ветка содержит весь интегрированный BE/AI/FE и документацию.
В исходные ветки других участников ничего не переписывается. Push/PR здесь не выполняется.

Локальный `main` входит в историю интеграции, поэтому подготовлено fast-forward
слияние без конфликтов. Перед публикацией закройте незавершённые изменения и проверьте:

```sh
git status --short
git log --oneline main..release/v4-main
git diff --stat main..release/v4-main
git merge-base --is-ancestor main release/v4-main
```

Первый вывод должен быть пустым, последняя команда — завершиться с кодом 0.
После просмотра выполните самостоятельно:

```sh
git fetch origin
git switch main
git merge --ff-only origin/main
git merge --ff-only release/v4-main
git push origin main
```

Это переносит финальную версию в main на GitHub. Пушить все промежуточные ветки
не требуется. Если какой-либо `--ff-only` завершился отказом, удалённый main изменился
несовместимым образом: остановитесь и согласуйте новые изменения локально, повторите
проверки. Не используйте force push или reset для обхода отказа.

После публикации проверьте статус workflow GitHub: локальная проверка не означает
успешный remote CI. Если main защищён правилами GitHub, следуйте установленному там
порядку публикации; не отключайте защиту ради этих команд.

## Локальный запуск после переключения на main

```sh
make v4-live-up
make v4-live-budget
make v4-cohorts
```

Основной сайт: http://localhost:15180. Статистика тестовых когорт: http://localhost:15181
в отдельном приватном окне. Локальный `.env.live-v4` и журнал бюджета в Git не входят.
Они сохраняются на этой машине; на другой нужны собственные настройки по
[полной инструкции](TESTING_FINAL_V4.md). Volumes не удаляйте.

Что показывать жюри: [JURY_DEMO_V4.md](JURY_DEMO_V4.md).
Проверки и оставшиеся ограничения: [UX/release review](docs/v4/ux-release-2026-11-14.md).
